# Brett vorm Kopf · Fehler & Ideen

Die öffentliche Anlaufstelle für Fehlermeldungen, Verbesserungsvorschläge und Funktionswünsche zu **Brett vorm Kopf**.

**[Zur Website](https://brett-vorm-kopf.de/) · [Vorhandene Meldungen ansehen](https://github.com/Palaron/BrettVormKopf_Official/issues) · [Neue Meldung erstellen](https://github.com/Palaron/BrettVormKopf_Official/issues/new)**

## Was ist Brett vorm Kopf?

Brett vorm Kopf ist eine Webanwendung zum Planen von Holzprojekten. Sie unterstützt bei Baugruppen und Stücklisten, der Zuschnittplanung für Plattenmaterial, Bohlen und Kantholz sowie bei Schnittfolgen, Materialbeständen und PDF-Unterlagen für die Werkstatt.

Projekte lassen sich im Gastmodus im eigenen Browser speichern und als JSON-Datei sichern. Die jeweils auf der Website verfügbaren Funktionen hängen vom veröffentlichten Entwicklungsstand ab.

Dieses Repository dient der öffentlichen Issue-Verwaltung. Der Anwendungscode und private Projektdaten werden hier nicht veröffentlicht.

## Einen Fehler melden

Bitte suche zuerst in den [bestehenden Issues](https://github.com/Palaron/BrettVormKopf_Official/issues?q=is%3Aissue), einschließlich abgeschlossener Meldungen. Gibt es den Fehler schon, ergänze das bestehende Issue um hilfreiche Informationen.

Für eine neue Meldung helfen uns:

1. **Ein aussagekräftiger Titel:** Welche Funktion verhält sich falsch?
2. **Schritte zum Nachstellen:** Welche Eingaben und Klicks führen zum Fehler?
3. **Erwartetes und tatsächliches Ergebnis:** Was sollte passieren, was passiert stattdessen?
4. **Umgebung:** Gerät, Betriebssystem, Browser und gegebenenfalls die verwendete Ansicht.
5. **Ein kleines Beispiel:** Bei Berechnungsfehlern anonymisierte Maße, Material, Stärke, Verbindung und relevante Sägeparameter; bei Darstellungsfehlern ein bereinigter Screenshot.

Ein verkleinertes Beispiel ist hilfreicher als ein vollständiges privates Projekt. Fehlermeldungen lassen sich mit einem GitHub-Konto über [„New issue“](https://github.com/Palaron/BrettVormKopf_Official/issues/new) einreichen.

## Eine Idee vorschlagen

Beschreibe, was du bauen oder erreichen möchtest, was dir dabei derzeit fehlt und wie dir die gewünschte Funktion helfen würde. Ein konkreter Anwendungsfall erleichtert die Planung. Bitte unterschiedliche Wünsche als getrennte Issues erfassen.

## Was passiert mit einer Meldung?

Issues werden geprüft und bei Rückfragen kommentiert. Ein eingereichter Wunsch ist noch keine Zusage für einen Umsetzungstermin. Ebenso bedeutet eine geschlossene Meldung nicht automatisch, dass eine Änderung bereits auf der öffentlichen Website verfügbar ist; der jeweilige Hinweis zum Abschluss beziehungsweise zur Veröffentlichung ist maßgeblich.

## Öffentlich heißt öffentlich

Issues, Kommentare und Anhänge in diesem Repository sind öffentlich. Bitte keine Passwörter, Schlüssel, persönlichen Kontaktdaten, vertraulichen Projektdateien oder Sicherheitslückendetails veröffentlichen. Screenshots und Beispieldaten vor dem Hochladen bereinigen.

Die Website legt keine Meldungen automatisch an und übernimmt keine Werkstattdaten in ein Issue. Du entscheidest selbst, welche Angaben du auf GitHub veröffentlichst.
